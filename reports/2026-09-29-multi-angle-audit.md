## 二、18 个角度的问题、处理与余项

### 1. 数据规模与叙事口径

问题：18,817 是普查资源总量，不能直接当作当前可点击药材数；精品层、目录层和名称索引混成一个数字，会造成“宣称很大、点开很少”的落差。

处理：首页 KPI、入口卡、星图 tab 和页脚改为读取运行时数据；README 区分 18,817 资源叙事、902 精品卡、8,818 approved 名称索引和 106 目录项。索引旁固定说明“仅名称可检索，药性字段以精品卡为准”。

余项：继续补齐药典逐名证据，并把官方逐名复核、公开资料收载、待审候选做成可筛选的证据等级。

### 2. 构建管道与确定性

问题：扩容若靠手改生成文件，下一次构建会回退或出现本地有、线上没有。

处理：扩展数据由受版本控制的事实源、食药目录和图片清单确定性重建；构建器、扩展校验器、目录校验器和应用资源门禁共同拦截缺字段、错误分类、图片越界和预缓存异常；构建结果字节级稳定测试继续保留。

余项：为源快照增加机器可读的发布日期和哈希展示，并在 CI 中把源快照变化单独列出。

### 3. 名称清洗、别名与 review 边界

问题：症状短语、错别字、复合名和重复变体会污染搜索；直接删除无法立即核验的名称又会损失可追溯性。

处理：白名单、别名、形近字、症状词、“等”字、长度与明确分隔符拆分规则进入 build 和 validator。无法确认的条目保留为 review，默认检索隐藏；approved 仍不等于药典收载或临床推荐。

余项：导出人工复核批次（名称、来源行、触发规则、建议动作），供专家逐条回填。

### 4. 字段完整度与缺失语义

问题：把空白四气、归经或功效填成“看起来合理”的值，比缺失更危险。

处理：每张卡带 factStatus；完整、部分和基础记录在覆盖图与详情中区分。17 条 directory-only 记录只证明官方目录身份，首页来源区动态提示尚未补录属性。

余项：为字段级证据增加来源链接、取值原文和抽取方法三元组。

### 5. 图片准确性、许可与搜索优先级

问题：缺图会削弱视觉体验，随意用相似物种或生成图又会制造识别风险；图片文件数和来源记录数也容易被误读为同一个数字。

处理：扩容优先搜索 Wikimedia Commons / iNaturalist，保存作者、许可、原始页面、下载地址和 SHA-256；严格物种/分类匹配，无法确认的记录显示本地占位。当前 611 条来源记录对应 553 个唯一文件，覆盖 611 张卡；重复复用不会伪装成独立图片。本轮搜索未把不可靠候选放入运行时。

余项：按首页精选、 高频方剂、其余卡片的顺序补齐 291 个缺图；每批检索后先执行图片许可校验，再更新扩展数据。

### 6. 信息架构与页面数量

问题：食养、文化、典籍、来源等内容量较小却各占一个路由，会让用户不断进入薄页面。

处理：导航收敛为首页、探索本草、性味归经、配伍网络、学习舱五个主入口；病证药链留在“更多”作为完整关系视图；食养、文化、典籍和来源改为首页连续章节，收藏改为全局抽屉；旧 hash 安全重定向。

余项：新增专题必须同时满足数据量、独立任务、可持续更新三项门槛。

### 7. 首页阅读节奏与模块连续性

问题：不同模块各用一套背景色和卡片边界，像多个模板拼接；长页面没有阅读方向时，数据入口与文化叙事互相抢注意力。

处理：统一 surface-soft / surface-raised 语义层，首页大区块保持同一纸面底色，仅用边界和内层层级区分；新增七段章节导航、当前章节、1 / 7 进度和滚动进度条，阅读顺序为档案→学习→精选→食养→典籍→文化→来源。

余项：继续做真实设备色彩对比和长页面截图回归，重点观察古籍主题下的边界与低对比文字。

### 8. 三主题一致性

问题：主题切换如果只换页面背景，图表、焦点、抽屉和按钮仍可能使用旧颜色；字符图标在不同字体下会变形。

处理：主题按钮改为内联 SVG；日间、夜读、古籍三套语义色覆盖焦点、抽屉、图表文字和网格；动效遵守 prefers-reduced-motion。

余项：补主题快照、打印样式和高对比模式的最低可读性测试。

### 9. 收藏与本机状态

问题：收藏按钮、导航角标、抽屉列表和多标签页各自维护状态，会出现“已收藏但角标仍为 0”。

处理：收藏统一通过 herbal:favorites 事件更新；抽屉同步 aria-hidden / aria-expanded，Escape 关闭并把焦点还给触发按钮；storage 事件同步跨标签页变化；导出 JSON 和移除操作通过 aria-live 播报；无 localStorage 时退化为当前标签页内存。

余项：若未来加入跨设备同步，另行设计授权和冲突合并，不扩张本机隐私边界。

### 10. 搜索、目录懒加载与失败降级

问题：8,818 条名称索引不适合首屏一次性加载；网络失败时发布半个分块会产生重复或假空态。

处理：目录按 45 个块延迟加载，Worker/主线程兼容路径保留加载中、失败和重试状态；默认结果只来自 approved；搜索支持 aria-live、上下选中、Enter 跳转和 Esc 关闭。

余项：为极慢网络增加可取消任务和“已加载 X / 8,818”进度。

### 11. 图表可解释性与交互闭环

问题：只有浏览型图表时，评审看不到结论；没有口径和回到证据条目的路径，图表容易被误读为疗效排名。

处理：保留高频配伍、君臣佐使、共现强度、剂量分布、归经—功效流向、食养性味×用法、资料完整度和省级记录等图表；图表有方法说明、可访问名称和点击后的筛选/详情链接；剂量仅统计原始记录明确为正数克单位的样本。

余项：为每张图补一条读图结论摘要，让没有图表经验的评审也能快速理解。

### 12. 星图 Canvas 的 LOD、触控与键盘

问题：全量标签首屏拥挤，移动端拖拽、捏合、点星容易抢事件；Canvas 还需要给键盘用户可达路径。

处理：默认标签只保留药食同源与亮星，放大才逐级显示；双击聚焦、搜索聚焦、功效着色、已阅亮星、指针捏合和键盘缩放/方向键/Enter 接入同一状态源；移动端回归验证触控区域和图表不横溢出。

余项：增加可见的键盘焦点代理列表，并在屏幕阅读器中播报当前药名。

### 13. 联动状态与路由容错

问题：详情→方剂容易做，证候→方剂→药材的反向联动和旧链接兼容更容易遗漏；坏 query 不应阻塞整页。

处理：store 保存选中药材、方剂和浏览足迹；hash query 传递焦点；旧食养、文化、学习、收藏入口重定向到合并后的首页/抽屉；未知 hash 显示可恢复的应用内 404，非法编码不阻塞路由。

余项：将路由参数 schema 化，并在开发模式输出错误原因。

### 14. 无障碍语义与焦点管理

问题：图表 Canvas 默认对读屏器不可见，抽屉关闭后焦点可能丢失，动态搜索结果若无播报也难以理解。

处理：图表容器提供 role=img、标题/方法摘要和文字降级；抽屉有标题、状态播报、Escape 和焦点回收；主页章节导航使用 aria-current=location；按钮、链接、表单控件保留原生语义。

余项：补齐剩余图片 alt、动态列表 aria-setsize/aria-posinset，并用真实 NVDA/VoiceOver 做人工走查。

### 15. 移动端与响应式

问题：375px 容易暴露表格、抽屉、图表和固定导航问题；只看桌面截图会漏掉触控目标和横向溢出。

处理：Playwright Chromium + mobile 覆盖 375px 路由、触控目标、表格卡片化、网络纵向布局、主题按钮和抽屉；当前回归为 82 passed / 2 skipped。

余项：补充 iOS Safari 真机和 Android WebView 检查，尤其是 100dvh、backdrop-filter 与文件下载。

### 16. 性能、缓存与资源边界

问题：ECharts、图片和目录块容易让首屏等待；Service Worker 若预缓存全部图片会拖慢安装并占满存储。

处理：ECharts 本地自托管但不阻塞解析，目录/图片不进首屏预缓存；运行时缓存有数量上限，图表路由切换主动 dispose 实例和 ResizeObserver；当前应用门禁预缓存约 2.18MB。

余项：用 Lighthouse/PerformanceObserver 记录 LCP、INP、CLS 和缓存命中率，再决定是否拆分 ECharts 或引入 Worker 空间索引。

### 17. 离线、失败与更新体验

问题：未访问的图片和目录块本来就不可保证离线；若 UI 暗示全部离线可用，会产生错误承诺。

处理：PWA 只缓存应用外壳和访问过的有限资源；网络失败保留文字/占位降级；新 Service Worker 等待用户明确刷新，不强制打断阅读。

余项：为目录块和图片分别显示尚未缓存、网络失败、无可靠来源三种状态。

### 18. 隐私、合规与内容边界

问题：收藏和足迹属于用户行为数据；图片和传统功效文案容易被理解为诊疗建议。

处理：无账号、无遥测，状态只写本机；页面、README 与详情明确“仅供文化科普，不构成医疗建议”；来源、许可证、原始剂量单位和未录入字段公开。

余项：增加隐私模式下的清除本机数据入口，并把第三方图片域名、缓存行为和许可证摘要放进可展开来源说明。
