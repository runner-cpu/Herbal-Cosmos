## 二、从多个角度复查的问题与处理

### 1. 数据规模与叙事口径

问题：18,817、2,711、902、924、8,818 和 106 属于不同层级，若放在同一张卡片里会造成“宣传数字等于可点击记录”的错觉。

处理：首页 KPI、探索页标签和页脚由运行时数据注入；页面旁明确说明“索引层仅名称可检索，药性字段以精品卡为准”。README、覆盖报告和图片清单同步写明各数字的分母。

余项：2,711 仍是药典标准总数，不应被展示为本项目已逐名复核的药材；当前可机械复核的逐名药典证据仍需后续补齐，不能用 approved 数字替代。

### 2. 名称清洗、别名和 review 边界

问题：开放名称表包含症状短语、复合名、形近字和历史异名。全部删除会失去可追溯性，全部放出又会污染搜索。

处理：构建器执行噪声词、长度、分隔符拆分、规范化和别名合并；无法确认的候选进入 review，默认不参与检索和属性统计。validate-catalog 对重复 ID、重复规范名、噪声规则和 manifest 数字做门禁。

余项：1,487 条 review 需要专家或药典逐名证据分批复核；approved 只表示名称通过公开来源与规则，不表示临床有效性、药典收载或用药推荐。

### 3. 构建确定性与生成物漂移

问题：大体积生成文件很容易被手工编辑或因排序、换行、时间戳漂移，导致本地和 Pages 内容不一致。

处理：名称索引、食药目录、扩展卡片和图片清单均从受版本控制的输入重建；扩展层拆成 bootstrap、8 个小块和 finalizer，每块小于发布接口的单文件限制；CI 会执行 build 后的校验、语法检查和 inline runtime 检查。

余项：后续可把构建摘要哈希写入 manifest，让评审直接比较源快照与产物，而不是只看日期。

### 4. 字段完整度与缺失语义

问题：四气、五味、归经、功效、地区或来源缺失时，填入邻近药材的“合理值”比显示空缺更危险。

处理：每张卡保留 factStatus；完整、部分和基础记录在筛选、详情和覆盖图中分层；directory-only 只证明目录身份，缺失属性显示“未录入”。

余项：96 张 partial、3 张 legacy 记录需要逐字段来源补齐；下一阶段为每个字段增加“原文摘录—来源链接—抽取方法”三元组。

### 5. 图片物种准确性与许可证

问题：药材名称常对应药用部位或炮制品，而公开照片通常只能证明来源生物；相似物种、无许可图片或生成图会损害可信度。

处理：优先检索 Wikimedia Commons / iNaturalist，要求精确物种或提供商已索引的分类异名，并且许可证为 CC BY、CC BY-SA、CC0 或公版；每条记录保存作者、许可证、原始页、下载 URL、物种证据和 SHA-256。僵蚕与蚕沙共用 Bombyx mori 来源图时明确复用，不伪装为两张独立图。

余项：仍有 284 张卡显示占位；优先顺序是首页精选、高频方剂、矿物/树脂/炮制品，再处理名称歧义条目。不能为了覆盖率调用没有证据的图像生成替代真实物种照片。

### 6. 图片检索运行稳定性

问题：公共 API 可能返回 429、网络超时或无许可候选；批量脚本若中途失败，容易写入半条记录。

处理：检索器缓存响应、限制并发、重试一次并把排除原因写入清单；本轮遇到 429 时保留已有可靠结果，最终命令仍以 errors: [] 完成。--verify 检查文件存在、哈希和署名字段。

余项：应在 CI 中使用固定小样本 fixture 做离线回归，避免 CI 依赖实时公共 API；在线检索仍需人工抽样查看物种页面。

### 7. 首页信息架构与页面收敛

问题：内容少的食养、文化、典籍和来源页面独立存在会制造“路由很多、每页很薄”的错觉。

处理：主导航收敛为首页、探索本草、性味归经、配伍网络、学习舱五个入口；病证药链保留在“更多”作为完整关系图；食养、文化、典籍和来源改为首页连续章节，收藏改为全局抽屉。

余项：未来新增专题必须同时满足独立数据集、独立任务和可持续更新三个条件，否则继续并入首页。

### 8. 首页连续阅读和模块衔接

问题：不同背景色的大块模块会像拼贴页面，读者无法判断阅读顺序。

处理：统一 paper surface 层级，只用边界、内层底色和印章色作区分；首页加入章节导航、当前章节提示、进度条和连续的“档案→学习→精选→食养→典籍→文化→来源”顺序；移动端保持同一顺序而不重复渲染一份内容。

余项：真实设备的亮度、色温和高对比模式仍需人工复核，尤其是古籍主题下低对比辅助文字。

### 9. 视觉系统与主题一致性

问题：日间、夜读、古籍三主题如果只换页面背景而不换焦点、图表、抽屉和按钮，切换后会出现旧色残留。

处理：颜色、边框、阴影、图表调色板和焦点环使用主题变量；印章同时用于知识卡、分类卡、搜索建议和全局药丸条；动效受 prefers-reduced-motion 控制。

余项：补充打印样式与高对比主题快照，避免评审导出或投屏时丢失层级。

### 10. 星图 LOD、触控和键盘

问题：全量标签会造成首屏拥挤；Canvas 在移动端容易把拖拽、点击和页面滚动混在一起；默认 Canvas 对读屏器不可见。

处理：首屏只显示药食同源与亮星标签，放大后逐级显示；拖拽/缩放在有效区域内处理，边界时放行页面滚动；搜索、双击聚焦、功效着色和“已阅亮星”共享同一状态源；页面提供文本索引和详情链接作为降级路径。

余项：真实 NVDA、VoiceOver 和 TalkBack 走查尚未替代自动化检查；后续可增加可见的键盘聚焦星点代理列表。

### 11. 搜索、懒加载与失败状态

问题：8,818 条名称不适合首屏一次性塞入 DOM；分块加载中断时，空表格容易被误读成“没有数据”。

处理：名称索引按 45 个块延迟加载，approved/review 分层；搜索建议支持上下键、Enter、Esc，结果区域有 aria-live；加载、失败、无匹配和切回精品层都有明确状态与下一步入口。

余项：极慢网络下可增加“已加载 X / 8,818”的可取消进度提示，并让 Worker 版本和主线程回退共享同一索引协议。

### 12. 图表洞察与可解释性

问题：只有浏览型图表时，评审看不到结论，也不知道数值是否代表疗效排名。

处理：加入高频配伍、君臣佐使、共现强度、剂量分布、归经→功效流向、食养性味×用法、资料完整度和地区记录等图表；每张图配口径说明，点击可回到药材、方剂或证候证据条目；剂量图只统计原记录明确为正数克单位的样本。

余项：下一轮为每张图增加一行机器生成的“读图摘要”，并由人工确认措辞，避免把共现误写成疗效因果。

### 13. 路由联动与状态恢复

问题：详情→方剂较容易实现，证候→方剂→药材→星图的反向路径、旧 hash 链接和刷新恢复更容易遗漏。

处理：store 保存 selected herb、formula、syndrome、收藏和探索足迹；hash query 只传递可恢复的 ID，未知参数降级到应用内 404；跨页高亮和全局药丸条共用发布订阅。

余项：新增路由 schema 测试，覆盖旧链接、编码异常、刷新和前进/后退栈。

### 14. 收藏、足迹与本机隐私

问题：收藏按钮、导航角标、抽屉和详情态各自维护会出现不同步；足迹若没有边界会无限增长。

处理：收藏统一通过 herbal:favorites 事件更新，抽屉支持批量 JSON 导出和空态引导；足迹只保留有限 ID，数据只写本机存储，并在页面说明不上传账户。

余项：增加“清除本机数据”总入口和导入 JSON 的格式版本/冲突策略；不在未授权情况下增加云同步。

### 15. 无障碍与语义结构

问题：Canvas/ECharts、动态抽屉、搜索建议和图像卡片是自动化测试最容易漏掉的区域。

处理：补齐跳过链接、focus-visible、aria-expanded/aria-hidden、图表文字降级、语义化按钮和图片 alt；移动端回归覆盖触控目标与横向溢出。

余项：真实屏幕阅读器、颜色对比度测量、动态文字放大 200% 和减少透明度模式仍需手工验收。

### 16. 性能、缓存和离线边界

问题：ECharts、数据块和图片会同时抢占首屏；Service Worker 若缓存版本不变会把旧生成物继续发给用户。

处理：ECharts 本地托管，扩展数据拆块并按需加载，图片只在访问后进入运行时缓存；v8 cache key 与数据日期同步，旧缓存自动清理，更新由用户确认而非静默打断阅读。

余项：尚未在真实 Pages 上建立 Lighthouse 的 LCP/INP/CLS 基线，也未在 iOS Safari/Android WebView 做同等缓存压力测试；这些指标不能用 Playwright 功能通过替代。

### 17. SEO、分享和错误恢复

问题：SPA 深链接、分享卡片、favicon、404 和离线错误页会影响评审第一印象。

处理：保留静态 404、manifest、站点标题、描述、OG 和 favicon；无效 hash 回到应用内错误状态，不阻塞主页面；图表和图片失败有文字/占位降级。

余项：应在 Pages 线上实际抓取 meta、分享预览和 404 响应，而不是只检查源码。

### 18. 国际化与内容边界

问题：未完成的英文界面会造成中英混杂；传统功效文本又容易被误读为诊疗建议。

处理：暂不展示未完成的 EN 切换；页面和 README 明确“仅供文化科普，不构成医疗建议”，图片和资料来源单独标注，不把共现图表写成疗效结论。

余项：若恢复英文入口，必须一次性覆盖统计、筛选、空态、错误和图表摘要，并为医疗边界提供同等翻译。

### 19. CI、发布和可回滚

问题：数据扩容若只在本地验证，容易出现“本地有图、Pages 无图”或分支缓存未更新。

处理：GitHub Actions 串联构建、目录质检、图片许可校验、Web 资源校验、Node 回归和浏览器回归；发布时同时推进 main 与 gh-pages，并记录提交 SHA 与 Pages URL。

余项：本轮发布前仍需重新跑完整门禁、确认两个远端 ref，再核验线上 HTML 与关键数据版本；若远端移动，不使用 force push，先重新读取 ref。

## 三、下一批数据与质量工作

1. 按首页精选→高频方剂→矿物/树脂/炮制品顺序检索剩余 284 张占位图，每批不超过 100 条，先 --verify 再重建数据。
2. 将 1,487 条 review 分成可审计批次，记录触发规则、候选名称、来源行和复核结论，不直接批量提升为 approved。
3. 为 96 张 partial 和 3 张 legacy 卡补字段级证据，优先归经、四气五味和来源地区。
4. 建立线上 Lighthouse、真实设备、屏幕阅读器和打印样式基线；报告中同时记录环境、网络和浏览器版本。
5. 在不增加薄页面的前提下继续增强首页“读图结论—证据条目—相关方剂”的闭环。
