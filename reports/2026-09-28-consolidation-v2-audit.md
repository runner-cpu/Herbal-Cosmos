# 本草宇宙 V6 多角度审计与后续优化记录

审计日期：2026-09-28  
审计对象：codex/herbal-cosmos-upgrade 工作树  
审计重点：数据扩充是否可追溯、首页信息架构是否收敛、视觉连续性、图表解释力、交互闭环、可访问性、移动端、性能、SEO/PWA、测试与发布风险。

## 结论摘要

本轮将内容从“多个小入口、每页信息量不足”收敛为 4 个主入口：首页、探索本草、性味归经、配伍网络。学习舱与病证药链保留旧 hash 兼容，但落到首页学习路径或配伍网络的对应视图，避免继续扩大导航复杂度。

数据层已从 144 张基础卡扩展为 902 张可浏览知识卡、907 条运行时记录；名称索引构建出 8,818 条 approved 与 1,487 条 review；药食同源 106 条、方剂 50 条、证候 30 条。图片坚持“精确物种匹配 + 开放许可 + 可追溯来源”，目前 611 张有许可记录，291 张明确显示待补，不以相似图片或生成图片填充缺口。

首页新增“资料完整度 × 传统分类”矩阵，并把完整来源事实、部分字段记录、既有基础卡、开放图片、逐行来源分开说明。这样既提高了数据洞察力，也避免把资源规模、名称索引和精品知识卡混为一个数字。

## 多角度审计

| 角度 | 已发现的风险 | 本轮处理 | 当前证据/剩余限制 |
|---|---|---|---|
| 数据规模 | 旧版精品卡只有 144 张，首页容易给人“内容很多但可核验条目少”的落差 | 扩展至 902 张知识卡，50 方剂、30 证候、106 药食同源 | reports/data-coverage.json；距离“全药典逐条精品化”仍有字段与图片缺口 |
| 数据分层 | 资源总量、名称索引、精品卡、关系网络的口径不同，硬编码会造成首帧抖动或误读 | 运行时从生成数据注入计数；覆盖图明确分层 | 18,817、2,711 等仍只代表资源/标准规模，不能理解为当前逐条浏览量 |
| 名称索引 | 症状短语、错别字、复合名和变体可能污染搜索 | build 与 validate 共用清洗规则；approved/review 分层，review 默认隐藏 | 1,487 条 review 仍需人工抽样复核，不能直接升级为 approved |
| 权威性 | “有来源链接”不等于“药典核验” | 页面把来源、逐行来源、分类学、归经、地区、图片分开统计 | 现阶段没有把所有卡都提升为同一权威等级，文案需继续保持克制 |
| 图片许可 | 相似物种或无许可图片会直接损害评审可信度 | 保留作者、许可、来源 URL、下载 URL、物种证据和哈希；缺图显示待补 | 291 张待补，矿物、树脂、炮制品和名称歧义条目应优先人工检索 |
| 图片覆盖 | 扩容后卡片数增加，图片比例可能看起来下降 | 覆盖图同时显示开放图片数量与缺图数量，不隐藏缺口 | 当前图片覆盖约 67.7%，优先补首页精选和高频方剂用药 |
| 信息架构 | 食养、文化、典籍、来源内容过少却各自成页 | 并入首页长卷；主导航固定 4 个入口；旧路由做兼容映射 | 首页仍较长，后续可增加章节目录与当前阅读位置提示 |
| 导航复杂度 | “更多”菜单容易成为低内容页面的收容所 | 删除 navMore，只保留有实质内容的 4 个入口 | 兼容 hash 仍存在，但不再制造额外导航项 |
| 首页叙事 | 深色英雄区、浅色卡片区和经典页式模块之间容易割裂 | 统一纸面色系、边界、间距与分析区表面；减少突兀白卡和重阴影 | 深浅主题仍需在真实投影/低亮度屏幕上做一次人工对比 |
| 图表解释力 | 单纯数量图只能“浏览”，无法说明数据质量 | 新增完整度矩阵、可点击证据筛选和文本摘要 | 矩阵展示的是资料覆盖，不是药效强弱；后续可增加共现强度与剂量分布 |
| 图表可访问性 | Canvas 图表对键盘和读屏器不透明 | 图表旁提供摘要、证据链接和可键盘聚焦的筛选入口 | Canvas 本身仍不是原生表格；复杂图表应继续提供可折叠数据表 |
| 搜索与懒加载 | 全量索引一次性加载会拖慢首屏，失败时可能发布半成品 | catalog chunk 按需加载；失败重试不发布部分结果 | 需要在低速网络和首次冷缓存环境测量 LCP/INP，而不是只看文件大小 |
| 收藏闭环 | 收藏按钮、导航角标、抽屉不同步会破坏信任 | 统一 store 事件，角标、抽屉和卡片态共用同一来源 | 仍应补一次跨标签页 storage 事件回归，确保多标签行为一致 |
| 交互联动 | 旧页面之间上下文容易丢失 | selectedHerb、方剂/证候上下文和兼容 hash 保留；配伍视图可切换 | 星图复杂联动仍依赖 Canvas 状态，后续可增加更明确的“当前聚焦”文字状态 |
| 学习路径 | 学习舱单页内容少，独立入口会显得空 | 五步学习路径放到首页，旧 #/learn 映射到对应步骤 | 还可把答题错误类型沉淀为个人学习记录，但不能默认收集隐私数据 |
| 移动端 | 横滑模块、学习路径和固定控件可能制造页面溢出 | 375px 回归；横滑容器与页面宽度隔离；移动端关闭平滑滚动拦截 | 尚未覆盖 Safari iOS 真机、低端 Android GPU 与旋转屏场景 |
| 触控可用性 | 图表切换、收藏、菜单等小目标在手机上难点按 | 关键控件最小触控尺寸按 44px 回归 | 星图捏合/拖拽/点星仍建议在真机上抽样验证 |
| 无障碍 | 图表、搜索结果和动态状态可能没有语义反馈 | 补 aria-label、状态文本、原生链接与键盘路径；图表摘要可读 | 需继续用屏幕阅读器验证中文朗读顺序与焦点回收 |
| 主题与动效 | 夜读、日间切换时动效和背景层可能不连贯 | 三主题循环与 reduced-motion 测试保留；首页面纸面表面统一 | 水墨/古籍主题仍可进一步强化印章、批注、字体层级，但不能引入外部字体依赖 |
| SEO/分享 | SPA 深链接、描述和社交卡片容易缺失 | 保留 manifest、离线 shell 与路由兼容校验 | GitHub Pages 发布后仍需抽样检查 canonical、OG 图片和实际缓存头 |
| PWA/离线 | 旧缓存可能继续展示旧数据，数据块失败会造成错觉 | SW 版本化、预缓存预算校验、离线状态测试 | 大图不应加入预缓存；离线只承诺已访问 shell 与已缓存数据 |
| 工程可维护性 | 单文件和生成文件容易被手改，扩容后更难协作 | build:data、validate:data、validate:app、check:inline、Node 语法检查和浏览器测试串联 | 后续可把首页模块进一步拆成路由脚本，但需维持零构建部署能力 |
| 发布一致性 | main 与 gh-pages 不同 SHA 会使评审看到不同版本 | 发布步骤固定为同一 SHA 推送两个分支 | 推送后必须用 git ls-remote 和线上 HTTP 烟测确认 |

## 本轮修复的用户可见结果

1. 首页的食养、文化、典籍、数据来源和学习路径围绕同一长卷叙事，不再让用户在多个低内容页面之间来回跳转。
2. 探索本草同时提供精品卡与名称索引；索引层懒加载，review 条目不污染默认搜索。
3. 完整度矩阵支持键盘聚焦和证据跳转，点击某一覆盖维度即可进入对应筛选结果。
4. 收藏角标、抽屉、卡片状态由同一状态源更新；学习与旧路由仍可打开，不破坏外部链接。
5. 首页模块使用连续纸面表面与统一边界，主题切换和 375px 布局都有自动化回归。

## 下一阶段建议（按风险排序）

### P0：发布后立即抽样

- 对线上首页、#/herbs、#/qiwei、#/formula 做 HTTP 200、脚本版本、manifest 和数据块版本核对。
- 在 Chromium 桌面、375px 模拟器和一台真实 iOS/Android 设备各抽样一次：搜索、收藏、抽屉、配伍视图切换、矩阵证据跳转。
- 从 1,487 条 review 中抽样 100 条，记录误判原因与升级/保留依据，禁止用“数量达标”替代质量复核。

### P1：提高数据解释力

- 继续补齐 291 张图片，优先首页精选、21/50 方剂高频用药、矿物/树脂/炮制品；每条仍需开放许可与精确物种证据。
- 增加“方剂 × 药材”共现强度热力、君臣佐使角色分布、剂量分布等洞察图，并为每张图同步提供文本摘要和数据表。
- 在覆盖矩阵中增加时间版本与来源类型筛选，让用户区分官方目录、古籍映射、开放许可图片和项目整理记录。

### P2：性能与无障碍收尾

- 按图表路由拆分 ECharts 注册范围，真实测量冷缓存 LCP、INP、内存和移动端 GPU 负载。
- 用屏幕阅读器做一次完整中文流程测试；给 Canvas 图表提供可折叠原生表格作为等价信息通道。
- 增加 Safari iOS、低端 Android、窄屏横竖屏和高对比度主题回归。

## 发布门槛

只有以下条件同时满足，才把本轮标记为可发布：

- build、数据质检、应用质检、内联运行时检查和单元测试全部为 0 失败；
- Chromium 桌面与移动浏览器回归全部通过（允许显式标记的不适用测试）；
- git diff --check 无空白错误，工作区无临时文件；
- 同一 SHA 已同步到 origin/main 与 origin/gh-pages；
- 线上首页显示真实的 902 / 8,818 / 106 口径，图片待补数量仍诚实可见；
- 不把 18,817、2,711 等资源规模写成逐条已核验内容，不把 611 张图片写成全部卡片均有图。
