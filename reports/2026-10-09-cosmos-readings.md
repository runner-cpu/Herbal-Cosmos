## 四、批次 C · 星图引擎 V2

新建 `assets/js/pages/cosmos-engine.js`（21,842 字节，经典脚本——必须是经典脚本，否则 `file://` 双击直开会因 CORS 被拦）。

三步替代每帧渐变分配：

1. **光晕精灵预渲染**：按颜色 × DPR 生成 128×128 离屏 canvas 并缓存，每帧只做 `drawImage`。`warmSprites()` 在进入渲染循环前预热全部精灵（实测 ≤1.8ms），避免首帧夹带十几次离屏 canvas 创建。
2. **加色辉光**：`globalCompositeOperation='lighter'`，画完立即复位；按主题给不同 alpha（day 0.55 / night 1 / ink 0.72），浅色底防过曝。
3. **景深**：`depthBlur(zr)` 驱动精灵放大与降 alpha，远景成柔光斑、近景锐利——这是「宇宙」与「平面点阵」的分界。

**四种读法**（核心创新）：同一组 902 颗星回答四个问题。分类（13 色）/ 文献分布（首省 → 五大区）/ 药性（四气九级）/ 民族对照（有核准线索者亮、其余压暗）。切读法**只改颜色映射并重绘，不重建几何**。文献分布读法让青藏与西北自然成簇——多民族地区的药材在数据里本来就是一簇。

**首屏口径揭示**：微尘先来（「这里有很多」）→ 902 颗星依次点亮（「但只有这些能点进去」）→ 归位。`prefers-reduced-motion` 直接跳终态。这让「从 18,817 到 902」不需要一句文字就被看懂。

**降级**：四级，永不白屏。30 帧滑动平均，>20ms 降级、<12ms 稳定 3 秒回升。

## 五、批次 D · 民族对照层

**唯一新增结构**：`assets/js/data/ethnic-correspondence.js`，37 条，字段 `herbId / herbName / systems / note / source / status`。不新建体系页、不新建术语表、不重建 schema。

**门禁** `scripts/validate-ethnic-data.mjs`：herbId 必须存在于运行时 902 卡；`systems` 限 `tibetan|mongolian|uyghur|common`；无重复；`note` 过疗效断言词表（治愈/根治/特效/有效率/临床验证/推荐用药/替代药物/无毒副作用/包治/最好/第一/主治/疗效）；**`status:'approved'` 要求 `source.url` 以 `https://` 开头，否则自动降级 `review`**。

**关键取舍：门禁先上线，界面自己会隐藏。** 当前 0 条通过，于是：

- 星图民族读法按钮不渲染；
- 传承页「共同的本草」整节 `hidden`；
- 知识卡民族对照行 `hidden`；
- `?read=ethnic` 回落 `category`，不把用户带到空读法上。

门禁、容器、测试、覆盖报告全部就位，**补齐来源后不需要改一行代码**。

### 踩过的坑（都写进了第 14.1 节）

- `cosmos-engine.js` 的 `Math.random()` 是星尘初始位置，**无安全语义，属误报**，不改。
- `runtime.js` 四个渲染函数被标为中风险 XSS 入口，逐一核对确认**均已走 `esc()`**；记录为已核实，后续新增动态拼接须继续使用既有转义层。
