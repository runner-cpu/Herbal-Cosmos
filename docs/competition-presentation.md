# 本草宇宙 · 参赛叙事与三分钟演示

资料快照：2026-10-08，数据 v10。页面结构见[文化赛道框架](competition-framework.md)，具体收录数字以[生成数据账本](../reports/data-coverage.json)为准。本文用于介绍作品与组织演示，不推测比赛未提供的评分权重。

## 可复制的作品介绍

本草宇宙是一座以民族医药文化为主题的数字展馆。作品围绕“本草如何被认识、解释、配伍与传承”，设置序章和“源、道、术、传”四幕，并以文化传习和个人阅读旅程连接观众。我们让星图、性味矩阵与方剂网络成为阅读资料的入口：观众点击一颗星、一个色块或一味组成，都能回到具体知识卡与来源，而不只停留在视觉印象。

作品以中医本草与方剂为主要资料基础，并通过藏医药浴等有官方来源的专题呈现民族医药文化的多样性。中医的四气五味、归经与君臣佐使在各自理论语境下解释；藏医药浴保留自身的知识和实践名称，避免把不同民族医学归入同一套分类。

当前展馆可浏览902张知识卡、100首代表方剂与58个证候，另有8,818条已收纳名称索引和106项食药目录快照。624张知识卡有许可明确的来源生物照片，278张仍标为照片待补；同源图片复用后为562个唯一文件。数据层级、未知字段和图像来源都公开展示，名称索引不冒充完整知识卡，传统分类也不冒充临床效果证明。收藏、足迹和练习记录只保存在观众自己的浏览器中。

## 创新表达如何落在页面里

| 文化问题 | 页面与操作 | 观众获得的理解 |
|---|---|---|
| 一草一木如何进入知识？ | 从序章进入“源”，看首屏揭示动画，再点星点或精选药材 | 星图是本草意象；先看到“有很多”，再看到“只有这些能点进去”；可点对象对应真实收录记录 |
| 同一批药材还能怎么读？ | 切换星图四种读法：分类 / 文献分布 / 药性 / 民族对照 | 同一组902颗星回答四个不同问题；切到文献分布时青藏与西北自然成簇——多民族地区的药材在数据里本来就是一簇 |
| 古人怎样表达药性？ | 在“道”读四气五味说明，点矩阵，再打开知识卡 | 理论解释、样本计数与原资料连成一条阅读链 |
| 一首方怎样组织多味本草？ | 在“术”查看方剂网络与原组成 | 君臣佐使是传统分工语言；原方角色和剂量缺失时保持缺失 |
| 知识怎样代代相传？ | 在“传”查看藏医药浴、炮制等专题，打开官方名录；看「共同的本草」的来源门禁 | 技艺、生活与典籍是传承的不同载体；“本草”本就是各民族医药的统称，而本馆主体是中医本草 |
| 观众如何参与？ | 在“传习”答文化题，按反馈回读；从旅程面板返回资料 | 参与由解释、出处和复读构成，而非只有答题分数 |

视觉采用本草印章、星轨、五行文字与配色，以及日间、夜读、水墨古籍三主题。SVG开场与星图引擎V2分别承担不同交互——星图用光晕精灵、加色辉光与景深，减少动效偏好下直接呈现终态。创新点是“可理解、可操作、可追溯”的文化阅读过程，演示不以图表数量代替完成度。

**关于「共同的本草」要怎么说**：这一节当前是隐藏的，37条对照线索全部缺可核对来源，因此不显示。这本身就是一个可讲的点——“我们宁可让这一节空着，也不写一条查不到出处的民族用药对照”。如果现场被问到民族内容的比重，这比展示一张无来源的对照表更有说服力。

## 三分钟现场演示脚本

| 时间 | 页面与动作 | 建议讲述 |
|---|---|---|
| 00:00–00:25 | 打开序章，指向传说说明和典籍时间轴 | “我们把项目组织成一座展馆。这里先区分神农传说与后世本草文献；不同典籍的药物数、现代标准数保留各自单位，不把它们拼成虚假的增长曲线。” |
| 00:25–00:50 | 进入“源”，看首屏揭示动画，点六味精选中的枸杞子，查看知识卡 | “一草一木都有可读的资料入口。星图服务于文化表达，馆藏规模由实际902张卡决定；这里还能核对来源与照片许可。” |
| 00:50–01:15 | 在“源”依次切换星图的四种读法，停在“文献分布” | “同一批902颗星能回答四个问题：它属于哪一类、从哪里来、多寒多热、还有谁用过它。切到文献分布，青藏和西北自然就成了一簇——这是数据里本来就有的结构，我们只是让它第一次被看见。” |
| 01:15–01:40 | 进入“道”，读主五味图例，点击一个有记录的矩阵格 | “古人用四气五味表达药性。这里先给解释，再给样本；复合味型拆分计数，四气待补的记录也保留，让两个统计图的口径一致。点击即可看到哪些药材构成这个数字。” |
| 01:40–02:05 | 进入“术”，选择已有方剂，查看组成与证据；需要时切到样本洞察 | “君臣佐使帮助理解组方分工。网络显示本项目100首代表方中的文献关系；未标注的角色不自动补齐，古方剂量不擅自换算成统一排名。” |
| 02:05–02:35 | 进入“传”，展开藏医药浴专题；展示官方链接，再搜索食药目录中的一项 | “民族文化通过具体技艺和生活知识被传承。藏医药浴按自身名称与UNESCO条目说明；食药目录保留公告年份和逐项出处，收载不等于可以任意食用。” |
| 02:35–03:00 | 进入“传习”，回答第一道文化题，展示解释、回读入口与旅程面板；切换夜读或水墨主题 | “最后由观众参与：答题后能回到资料阅读，收藏与足迹组成个人旅程。我们希望观众带走的是一条可以继续阅读的文化线索，而不只是几个传统术语。” |

演示前可先访问一次需要使用的图表与图片，让本机形成访问缓存；这属于现场稳定性准备，不能作为首次访问性能的证明。深链接同样可以进入各幕，序章没有必须观看或倒计时解锁。

## 性能与完成度说明

图表库由仓库自托管，按页面使用加载；本轮从Service Worker安装预缓存移除ECharts，避免观众只读序章也被后台下载图表库。访问缓存按发布版本隔离，命中后不再次后台全量刷新。直接首次打开图表页时，若图表先于离线接管加载，会在接管后为已使用的库补缓存；不等待离线安装来阻塞图表渲染，补缓存可能再发出一次请求。名称索引45个分块仍在进入索引检索时按需下载；药材照片按访问保留最近120项，不预下载全部图库。

离线入口只由展馆入口的HTML更新。在线打开仓库中的Markdown框架文档不会替换展馆缓存；这些文档文件需要网络，不在离线时伪装成展馆页面。访问过的展馆与图表仍可从入口按Hash路由阅读。

## 如果被问到“为什么星图不用 three.js”

评审很可能问这个。答案不是“我们不会用”，而是“用了会更差”：

- `file://` 双击直开是本项目对体验者的承诺，而 three.js r150+ 只发 ESM，`<script type="module">` 在 `file://` 下被 CORS 拦截。
- r147 及更早还有 UMD 形态，但那个版本已经不带 `EffectComposer` / `UnrealBloomPass`——引入它反而拿不到想要的辉光。
- 体积 +600KB，与首屏预算和现有的按需加载策略直接冲突。
- 需要重写已经跑通的四级降级、无障碍、reduced-motion 与 PWA 缓存，并让已有的星图交互测试全部失效。

关键认知是：**Canvas 2D 的瓶颈从来不在粒子数，而在绘制方式。** 消除每帧的渐变对象分配之后，Canvas 2D 可以稳定绘制数千至上万粒子。用精灵 + 加色 + 景深拿到的，正是目标视觉效果的绝大部分。实测数据可以现场调出：首帧 26.2ms、稳定帧 8.6–12.6ms、桌面 6,902 粒子。

完整知识卡数据目前仍由13个有序`defer`数据脚本加载，原始合计约915KB，逐文件gzip估算约166KB。这里包含基础精选、扩展引导、9个分块和最终合并脚本；不能宣称完整知识卡已按页面懒加载。ECharts原始约1,034KB，gzip估算约336KB。本地预览服务器未启用压缩，因此浏览器记录的原始响应字节与gzip估算是两种测量，后者不等于Pages实际传输。初次安装外壳缓存仍可能再次请求已加载脚本；图片缩略图、WebP管线与全量数据按页面延后加载仍是后续建设项。

整改前在本地Chromium中模拟120ms延迟、200KB/s下载和四倍CPU限速，序章DOM就绪约7.65秒；该结果只说明当前未压缩、全量数据初始化的瓶颈，不能作为线上或真实移动设备的普遍耗时。本轮没有以同条件限速重测证明首屏时间改善，只报告上表流量变化。浏览器回归覆盖首次序章无预取、访问后命中无后台重下、从序章进入图表后离线重载，以及直接首次进入图表的离线缓存衔接。

现阶段的其他边界包括：278张知识卡照片待补、1,487条名称待审、古籍影印页码仍需补齐、现行标准与目录需持续更新、各民族医药专题需独立文献及授权纪实素材、真实移动设备与屏幕阅读器尚需专项验收。这些状态与作品已有文化阅读链同时公开，演示时保留真实缺口。
