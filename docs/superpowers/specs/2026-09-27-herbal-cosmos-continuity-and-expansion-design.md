# 本草宇宙：数据扩容与首页连续性设计

日期：2026-09-27

## 目标

本轮在不夸大数据口径的前提下扩大可浏览内容，优先补齐开放许可图片，并将首页改造成一条连续的本草叙事。内容较少的锚点不再伪装成独立页面；图表和交互要帮助用户理解数据，而不是只增加装饰。

## 当前基线与约束

- 名称索引、精品卡、药食同源、方剂和证候均由生成脚本产出，禁止直接编辑生成文件。
- 当前生产基线为 608 张精品卡、106 种药食同源、50 方剂、30 证候；名称索引按 approved/review 分层。
- 18,817、2,711 等数字属于资料普查或药典统计，不能写成当前逐条可浏览数量。
- TCM_KG、origin 和图片都必须保留来源与限定语：公开资料整理、资料记录地区、物种参考图，不推导药用部位/炮制/功效/安全性。
- 当前应用为零构建 SPA，继续使用原有脚本、CSS token 和 ECharts，不引入新的构建链。

## 方案一：小步扩容（备选）

只把精品卡提升到约 700，先修首页视觉和入口收敛。优点是风险低、验证快；缺点是图片覆盖和“数据继续扩充”的体感有限，仍会留下大量完整源事实未利用。

## 方案二：证据优先的分阶段扩容（推荐）

将完整源事实中可安全展示的记录提升到约 760–800；排序优先使用已有开放许可图片，其次才加入无图记录。每次构建同时产出覆盖率报告，图片检索脚本写入可复核的作者、许可、来源 URL 和哈希。无图记录仍可进入精品层，但明确显示占位状态，并由质检限制占位比例和必备字段。此方案能最大化真实数据利用率，同时不把图片或资料地区误称为权威证据。

## 方案三：全量药典卡片（暂不采用）

直接以药典 616 种为卡片目标并为全部卡片补图。它的叙事最简单，但当前逐名可复核证据和图片来源不足，容易把统计总量误读成已核验卡片，也会显著扩大移动端资源负担。

## 设计细节

### 1. 数据管道和图片来源

build-expanded-data.mjs 将目标阈值从 600 改为 780（当完整事实不足时使用实际可安全数量，并让验证脚本报告缺口）。新增 data-coverage 字段：completeFacts、imageBacked、placeholder、originCovered、sourceCovered、imageCoverageRatio。构建排序依次考虑：字段完整、已有图片、来源记录、分类均衡、名称稳定排序。

图片先运行 fetch-herb-images.mjs 的 Commons/iNaturalist 查询；只接受白名单开放许可，沿用现有哈希与本地文件校验。扩容后的卡片必须在 herb-images.json 中有记录或明确进入占位清单；不下载无法复核许可的图片。首页显示“有来源图片 / 占位图”覆盖率与链接到来源说明的入口。

validate-expanded-data.mjs 增加目标阈值、字段完整度、图片 manifest 一致性、占位比例上限和报告一致性检查。任何图片文件缺失、许可字段缺失或生成统计不一致都会失败。

### 2. 首页信息架构

主导航继续只有：首页、探索本草、性味归经、配伍网络、学习舱。更多菜单只保留病证药链这一有完整交互的次级路由；食养同源、文化非遗、数据来源改为首页区块或折叠内容，并保留可复制的锚点但不再出现在“更多”菜单。

首页顺序保持星图英雄区 → 数据档案 → 洞察图 → 分类/学习路径 → 精选本草 → 食养同源 → 典籍时光 → 文化非遗 → 关于/来源。区块之间使用同一 paper 基底、统一 section padding、边界和卡片半径；用细线、节点和轻微明度变化表达层级，不使用突然切换的整块深色背景。

### 3. 洞察与交互

新增“数据层进度”图表：显示精品卡、名称索引、药食目录、图片来源四个真实计数；旁边给出一句自动生成的文字结论。现有图表的点击事件统一跳转到可解释的筛选/详情，并补充键盘焦点和 aria-label。

目录加载改为 4 个并发分块，发出 herbal:catalog-progress（已完成、总块数、条数）和失败事件；页面以骨架/进度显示，不把未加载状态显示成 0。失败块可单独重试，Worker 初始化仍在全部 approved 条目加载后执行。

最近探索和已阅亮星沿用现有 store/localStorage，不新增第二套收藏数据源；首页和星图使用相同的事件名称。尊重 prefers-reduced-motion，视差和过渡在减弱动效下关闭。

### 4. 验收和发布

- 构建后精品卡达到约 760–800（或报告明确说明真实上限），药食 106、方剂 50、证候 30 不回退。
- 图片来源 manifest、占位状态和覆盖率报告互相一致；所有新增图片可追溯到开放许可来源。
- 更多菜单只出现病证药链；首页仍可访问食养、文化和来源内容。
- 首页模块背景、间距、边界连续；375px、768px、桌面无横向溢出。
- npm.cmd run build:data、npm.cmd run validate:data、npm.cmd run validate:app、npm.cmd test、npm.cmd run check:inline、全部 JS node --check、npm.cmd run test:browser:ci 和 git diff --check 均通过。
- 通过后以同一 SHA 推送 origin/main 与 origin/gh-pages，并检查两分支指向一致、Pages 返回成功。

## 不在本轮范围

- 不打开半成品英文界面。
- 不为缺少证据的记录编造药典权威或功效结论。
- 不引入 ECharts 按需打包或新的构建系统；该项作为后续性能专项。
