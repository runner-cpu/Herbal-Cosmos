# 本草宇宙：数据可信度与交互体验升级设计

**日期：** 2026-09-23  
**状态：** 已完成对话设计确认，等待书面规格复核  
**目标：** 在保持静态托管、零运行时构建和本地可打开的前提下，修复本草名称索引可信度，合并低内容页面，补充洞察图表与跨页联动，并建立可持续的自动质检和移动端回归体系。

## 1. 范围与交付策略

采用“可验收的分层演进”，按以下顺序交付，每一层都保持网页可运行、可回退：

1. 数据可信度：可复现来源、名称规范化、approved/review 分层、质检与口径文案。
2. 信息架构与洞察：拆分单文件、重排首页、收藏抽屉、四张洞察图和典籍详情。
3. 联动与视觉：上下文条、星图 LOD 与聚焦、跨页定位、足迹、古籍主题和动效治理。
4. 性能与工程：目录分块、Worker 与 file 协议回退、CI、桌面和移动浏览器回归。

本轮覆盖用户列出的完整范围。不会新生成图片；现有本地图片继续复用。若后续确需新建栅格资产，必须调用全局 `codex-image.cmd`，并保存到 `output/imagegen/`。

## 2. 数据权威口径

### 2.1 药典数字的含义

《中国药典》2020 年版一部的“2,711”作为中药标准总数展示，不再描述为 2,711 味药材名称。默认名称白名单采用公开资料可核验的药材与饮片目录，约 616/617 味；最终页面显示构建产物中的精确条数，并在来源说明中解释统计差异。

### 2.2 可审计输入

新增受版本控制的数据源目录，保存：

- 药典药材与饮片规范名主表；
- 古籍名称到规范名的别名映射；
- 繁简、异体和已确认形近字映射；
- 每份来源的公开 URL、获取日期、许可/使用说明与 SHA-256；
- 原始候选名称及其来源引用。

构建不得再依赖未提交的 `.tmp-herb-map-unzip` 或 `.tmp-classics`。第三方公开来源只用于形成可追溯候选和目录依据；没有充分依据的名称不得进入 approved 层。

### 2.3 构建流程

`scripts/build-herb-catalog.mjs` 按固定顺序处理：

1. 去除 BOM、空白、剂量、括注和明确制剂后缀。
2. 统一繁简与已核验异体字，例如“川貝→川贝”“皂角剌→皂角刺”。
3. 仅按可见分隔符拆分复合候选，拆分片段分别匹配；“泽泻沙参”这类无分隔符连写不得猜分。
4. 检测疼痛、抽搐、烦躁、苍白、破溃等症状词，检测“等”字、句式词和超过 8 个汉字的名称。
5. 以药典主表或古籍别名映射命中规范名。
6. 以规范名聚合来源和 `aliases`，生成与输入顺序无关的稳定 ID。

输出条目至少包含：`id`、`name`、`aliases`、`sourceRefs`、`status`、`reviewReasons` 和 `note`。

- `approved`：命中药典主表，或别名映射能追溯到规范名。
- `review`：未命中、疑似症状/句子、无分隔符复合名、超长、别名冲突或来源不足。

“规则剔除”是从默认检索面剔除，不删除原始候选。review 条目保留在审计产物和噪声报告中。

### 2.4 质检规则

`scripts/validate-catalog.mjs` 对 approved 层执行硬失败检查：

- 出现症状词、“等”字、句式词或长度大于 8；
- 规范名重复、alias 同时指向多个规范名或稳定 ID 冲突；
- 缺少来源引用、状态非法或 approved 未命中权威映射；
- 生成清单、分块 manifest 与统计摘要不一致；
- 页面引用的本地图片不存在。

review 层输出按原因分组的 `reports/catalog-review.json` 和人类可读摘要，但其存在本身不阻断构建。

## 3. 文件与运行架构

保持原生 HTML/CSS/JavaScript 和静态托管，不引入前端框架。`index.html` 只保留语义结构、全局壳和按顺序加载的经典 `defer` 脚本；不使用原生 ES module，以避免 `file://` 直接打开时的浏览器跨域差异。

建议边界：

- `assets/css/`：令牌/主题、基础布局、组件、路由页面、响应式。
- `assets/js/core/`：store、hash 路由、目录加载器、通用 DOM 与存储工具。
- `assets/js/components/`：导航、搜索、收藏抽屉、上下文条、印章。
- `assets/js/charts/`：聚合函数、ECharts 管理器、各洞察图。
- `assets/js/pages/`：首页、探索、性味、配伍、病证、食养、文化、学习与详情渲染。
- `data/catalog/`：manifest、首字/哈希分块和 review 审计产物。
- `tests/`：Node 单元测试与 Playwright 浏览器测试。

精品 144 味、21 首方剂、18 个证候和首页必要内容同步加载；全量目录不进入首屏关键路径。

## 4. 信息架构

### 4.1 导航

主导航固定为：首页、探索本草、性味归经、配伍网络、学习舱。更多菜单只放病证药链、药食同源、文化与非遗。收藏不再作为导航路由，改为全局按钮和右侧抽屉。访问旧 `#/saved` 时打开抽屉并回到当前或首页内容，避免死链。

### 4.2 首页长卷

顺序固定为：

1. 星图英雄区；
2. 本草档案四层口径；
3. 功效分类速览；
4. 六大入口；
5. 五步学习路径；
6. 精选本草；
7. 食养同源横滑条和“性味 × 用法”热力小图；
8. 典籍时光；
9. 文化非遗三张精选卡与“查看全部”展开；
10. 关于项目。

首页、星图页和搜索区域统一展示：“索引层仅名称可检索，药性字段以精品卡为准。”

### 4.3 独立页面

- `#/food` 保留代表数据的完整浏览、筛选和热力矩阵。页面必须显示当前实际样本数，不能把 106 种国家目录误写成当前已结构化 106 条。
- `#/culture` 保留六项完整浏览；首页只展示三项精选。
- `#/learn` 保留交互测验；首页五步分别携带 step query 进入对应学习步骤。答题反馈使用当前卡片内的轻量浮层。
- `#/zheng` 与 `#/formula` 共享 URL 和 store 高亮状态。

## 5. 洞察图表

所有统计从现有结构化数组即时聚合，不手填结论。图表标题旁显示样本口径。

1. 高频配伍排行：统计每味药在 21 首方中的出现方数，按频次降序的横向条形图；点击药名选中该药并定位配伍关系。
2. 君臣佐使分布：每首方一行，按君/臣/佐/使堆积计数；点击区段聚焦该方及对应角色药材。
3. 归经→功效桑基图：从 144 味精品卡展开“归经—功效类别”关系，边权为药材数；点击边或节点打开证据检查器。
4. 性味×用法矩阵：从实际 FOODS 样本聚合性味与用途，点击单元格显示具体条目；首页用紧凑版，食养页用完整版。

典籍柱图按朝代分段着色，并通过 ECharts `markArea` 提示时代。点击柱形打开就地详情浮层，显示数据中已有的药、方、图构成；缺少依据的字段显示“未录入”，不以零值代替未知。

## 6. 全局联动与状态

store 增加或规范以下状态：

- `selectedHerb`：规范药材对象；
- `selectedFormula`：方剂 ID；
- `selectedZheng`：证候 ID；
- `viewedHerbs`：已阅药材 ID 集合；
- `motionEnabled`：用户动效偏好；
- `theme`：day/night/classic。

store 提供订阅和精确通知。URL query 是可分享状态，store 是当前会话单一事实源，localStorage 只保存收藏、足迹、主题、学习统计和动效偏好。存储不可用时退化为会话内状态。

选中药材后，导航下显示药丸上下文条：规范名、印章、归经，以及星图、热力矩阵、配伍网络、相关方剂四个入口。搜索建议、首页分类和上下文条统一使用印章视觉。

病证图点击方剂进入 `#/formula?f=<id>&from=zheng&z=<id>`；配伍检查器提供返回关联证候。雷达图通过离点击位置最近的顶点识别指标，并进入对应性味或归经筛选。

## 7. 星图与动效

星图数据以规范药材 ID 去重。标签采用三层 LOD 和屏幕空间碰撞检测：

- 默认层：当前选中、悬停、药食同源、收藏/已阅和少量高权重亮星，限制同一视口标签上限。
- 中级缩放：增加高频方剂药材和当前功效类别。
- 高级缩放：在仍经过碰撞检测的前提下显示更多名称。

搜索命中后执行缓动旋转/缩放并短暂高亮；双击星点固定为焦点；功效着色开关在统一色与类别色之间切换。已阅药材显示外圈“亮星”标记。

首屏使用现有星云铺满宽度并加入低幅度滚动视差。页面同时遵守系统 `prefers-reduced-motion` 与站内动效开关；任一项要求减少动效时，视差、公转、飞行和非必要过渡停止或改为瞬时定位。

## 8. 主题与视觉系统

新增 classic 主题：米黄纸底、墨色正文、朱砂批注、低饱和青绿辅助色、楷体/宋体标题。主题切换为三态选择，图表颜色和 tooltip 同步更新。现有 day/night 语义保持兼容。

印章扩展到首页功效分类、搜索建议、上下文条和收藏抽屉，但不在每个普通按钮上重复。焦点环、44px 触控目标、键盘导航和语义标签在三种主题中都必须清晰可见。

## 9. 目录懒加载与回退

GitHub Pages 和本地 HTTP 环境优先启动 Web Worker，由 Worker 加载目录 manifest/分块、执行规范化查询并返回分页结果。首屏不加载完整目录。进入索引模式或首次目录搜索时才启动 Worker。

`file://` 环境若 Worker 或 fetch 不可用，则通过动态 `<script>` 按需加载兼容分块，并在主线程分批查询。兼容路径必须提供加载中、加载失败、重试和已加载状态。目录失败不得影响 144 味精品卡、方剂、图表和页面导航。

## 10. 自动化验证与 CI

Node 内置测试覆盖：

- 名称标准化与繁简/异体映射；
- 明确分隔符拆分和无分隔复合名进入 review；
- 症状词、“等”字和超长条目分流；
- aliases 聚合、冲突检测和稳定 ID；
- 高频配伍、角色分布、桑基边权与食养矩阵聚合；
- hash query 的解析与序列化。

Playwright 作为开发/CI 依赖，不进入运行时包。浏览器回归至少覆盖：

- 1440px 桌面：首页顺序、四张图、收藏抽屉、三主题、上下文条；
- 768px 与 375px：星图拖拽/缩放/点星、热力图证据项、抽屉和导航；
- 目录首次按需加载、review 名称不出现在默认结果；
- 病证→方剂→药材→星图闭环；
- 多次切换含图表路由后 ECharts 与 ResizeObserver 活跃实例数不增长；
- `prefers-reduced-motion` 下无持续公转和视差。

GitHub Actions 依次运行目录构建确定性检查、`validate-catalog.mjs`、Node 测试、JavaScript 语法检查、图片路径检查和 Playwright smoke。

## 11. 错误处理与透明原则

- 任何无法确认的药名都进入 review，不静默删除，也不展示为已确认药材。
- 任何没有数据依据的药性、典籍构成或用途字段都显示“未录入”，不推断。
- 目录加载、ECharts 初始化和 localStorage 失败均显示局部错误状态；其他路由继续可用。
- 导出收藏生成包含版本、导出时间、药材 ID 和规范名的 JSON；浏览器阻止下载时提供明确重试提示。
- 页面继续保留“文化科普，不构成诊断或用药建议”的边界声明。

## 12. 完成标准

只有同时满足以下条件才可提交最终实现：

1. 用户列举的已知噪声均不出现在默认搜索和 approved 目录。
2. approved 目录可追溯到受版本控制的主表或别名映射，review 报告可读。
3. 首页顺序、收藏抽屉、四张洞察图、典籍详情和三主题可操作。
4. 全局上下文条、星图三项增强、病证/配伍双向联动、雷达钻取和足迹可操作。
5. 全量目录不在首屏加载，HTTP Worker 与 file 协议回退都通过验证。
6. Node、目录质检、语法、图片、浏览器和移动端回归全部通过。
7. README 更新数据口径、运行方式、文件结构和验证命令。
8. 工作树只包含本次改造文件；提交后推送到 `origin/main`，并以远端提交哈希确认发布。
