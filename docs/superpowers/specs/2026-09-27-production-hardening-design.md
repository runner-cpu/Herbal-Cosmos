# 本草宇宙：多维生产审计与平衡加固设计

**日期：** 2026-09-27

**状态：** 已实现并通过发布候选验收

**基线提交：** 7497ccdd3d4988450705a5c44fc8a1892c3a7773

**目标：** 保持现有新中式视觉、数据口径、静态托管和零构建运行方式，对上线版本做一次可验证的生产级加固，同时兼顾评审弱网演示与公网首次访问。

## 1. 已确认的方向

本轮采用“平衡升级”：

- 不迁移框架，不重写数据层，不改变公开数据口径。
- 加入轻量 PWA、版本化缓存、离线和更新状态反馈。
- 消除 ECharts 对 HTML 解析的阻塞，不做高风险的 608 张知识卡深度分块。
- 修复导航、搜索、图表文字替代、未知路由和移动键盘路径。
- 补齐 SEO、隐私说明、404、依赖锁定、资源预算和移动 CI。
- 新图片不在本轮范围；现有开放许可图片继续按来源清单管理。

## 3. 架构与数据流

### 3.1 页面加载顺序

index.html 的内容和现有模块顺序保持不变。ECharts 从 head 移到 body 末尾、现有数据脚本之前。这样浏览器可以先完成 HTML 解析，同时仍保证 runtime 和 insights 执行时全局 echarts 已存在。

不把脚本统一改成 defer，也不把经典脚本改成 module；原因是项目仍承诺可通过本地 HTTP 和 file 协议打开，批量改变执行时机会增加全局数据与模块初始化竞态。

### 3.2 PWA 文件

新增：

- manifest.webmanifest：名称、短名称、主题色、背景色、standalone 展示方式、start_url 和现有 SVG 图标。
- sw.js：版本化预缓存、导航回退、运行时缓存和旧缓存清理。
- assets/js/core/app-shell.js：注册、在线状态、更新提示和安装状态的渐进增强。

Service Worker 只在 http/https 且浏览器支持时注册。file 协议不注册，不显示错误。

### 3.3 缓存边界

预缓存页面外壳：

- 根页面、404、manifest 和 favicon；
- 两个 CSS 文件；
- 自托管 ECharts；
- 首屏需要的数据脚本、运行时、组件和页面模块；
- Worker 脚本与目录 manifest，但不预取 45 个目录分块；
- 不预取 547 张图片。

请求策略：

- HTML/navigation：网络优先，失败时返回已缓存首页。
- 版本化核心静态资源：缓存优先，后台更新。
- data/catalog 分块：访问后缓存，最多保留全部 45 块。
- images：访问后缓存，最多保留最近 120 个同源图片响应。
- 外部链接和非 GET 请求：不拦截。

激活新版本时清理旧版本缓存。新 Worker 不主动 skipWaiting；页面检测 waiting 状态并展示“有新版本”提示。用户确认后发送 SKIP_WAITING，controllerchange 时刷新一次。

### 3.4 状态 UI

页面壳新增一个 aria-live=polite 的全局状态区域：

- 离线：说明当前显示已缓存内容，未访问图片或目录可能不可用。
- 恢复在线：短暂提示连接已恢复。
- 有更新：提供“刷新更新”和“稍后”按钮。
- 注册失败：不打断用户，只在开发控制台记录一次；普通浏览继续。

状态 UI 使用三主题令牌、移动安全区和减少动态效果规则。

## 4. 导航与路由

### 4.1 五主入口

主导航固定为：首页、探索本草、性味归经、配伍网络、学习舱。新增原生 details/summary “更多”菜单，包含病证药链、首页食养同源、文化非遗和数据来源锚点。

菜单要求：

- summary 可通过 Enter/Space 操作；
- 点击菜单项或导航到其他路由后自动关闭；
- Escape 关闭并把焦点还给 summary；
- 点击外部关闭；
- 当前处于病证路由时，“更多”显示当前态；
- 移动汉堡展开时保持至少 44px 触控目标。

### 4.2 未知路由

index.html 新增 data-route=not-found 页面。路由解析遇到未知值时渲染该页面，并显示原始安全转义路径。页面提供首页、探索本草和数据说明入口。

根目录 404.html 是无脚本也可使用的品牌化页面，解释 GitHub Pages 地址可能无效，并链接到站点根与主要入口。它不伪造 HTTP 200 的 SPA 路由。

## 5. 搜索与键盘

全局搜索输入采用 role=combobox，并具备：

- aria-label、aria-autocomplete=list、aria-controls、aria-expanded；
- 目录首次加载时 aria-busy=true；
- 每个结果具有稳定 option ID；
- 上下键改变视觉激活项并同步 aria-activedescendant；
- Enter 打开当前激活结果；没有激活项时沿用精确唯一命中的跳转规则；
- Escape 清空激活状态、关闭列表并保留输入焦点；
- aria-live 状态只播报结果数量、正在加载和无结果，不重复朗读整张列表。

搜索仍以规范名显示结果；别名只参与匹配。名称索引结果继续明确“仅名称索引”。

## 6. 图表文字替代

chartManager 在初始化图表时为容器建立可读名称，来源依次为：

1. 同一面板内的 h2/h3；
2. cap 或 chart-method 口径；
3. 当前样本数或现有证据文字。

图表容器使用 role=img 和 aria-label，不把内部 canvas 当成可操作控件。具备点击钻取的图表继续通过旁边的证据检查器提供真实链接；共现、剂量和已存在的数据表保持可键盘访问。

关键洞察新增可折叠文字摘要，内容由现有聚合结果生成，不手写静态结论。ECharts 不可用时显示相同摘要和已有 fallback 文案。

## 8. 应用级验证与资源预算

新增 scripts/validate-web-app.mjs，并由 npm run validate:app 调用。检查：

- manifest、sw、404 和 app-shell 存在且非空；
- manifest 的 start_url、scope、图标和主题字段合法；
- Service Worker 预缓存引用全部存在；
- index 含 canonical、robots、Twitter、OG 尺寸、JSON-LD 和 manifest；
- ECharts 不在 head，且在 runtime 之前加载；
- 页面没有新增外部运行时脚本或样式；
- 关键内部 href/src 可解析；
- 单个运行时 JS 上限：ECharts 1.1MB、生成数据 700KB、runtime 100KB、其他手写模块 40KB；
- 预缓存页面外壳总量不超过 2.5MB，不包含 images/herbs 或 data/catalog/chunk；
- 404 包含回站入口，隐私与医疗边界文案仍存在。

预算是防回退门禁，不宣称网络传输性能评分。GitHub Pages 的压缩和用户网络情况不由本地文件大小单独代表。

## 10. 失败与降级原则

- Service Worker 不支持或注册失败：普通在线页面完全可用。
- 缓存写入失败或存储不足：不阻止请求返回，继续网络模式。
- 离线且资源未缓存：局部错误态说明需要联网，不把未知内容显示为空数据。
- ECharts 失败：保留标题、口径、文字摘要和证据链接。
- localStorage 不可用：收藏、足迹与主题退化为当前会话，不上传到服务器。
- 任何应用壳改动不得改变 approved/review 判定或给缺失字段填默认事实。

## 12. 完成标准

只有同时满足以下条件才发布：

1. 现有数据规模与来源口径不回退，所有数据和图片验证为零错误。
2. ECharts 不再阻塞 head，应用资源预算通过。

4. 主导航为 5 项，更多菜单和搜索组合框可完整键盘操作。
5. 未知路由、404、离线、图表失败均有可恢复路径。
6. SEO、分享、隐私和内容边界元信息完整且不夸大医疗或药典口径。
7. 单元测试、桌面浏览器、375px 移动浏览器、语法、构建确定性和资源验证全部通过。
8. 最终工作树干净，同一提交快进推送 main 与 gh-pages。
9. GitHub Catalog quality 与 Pages deployment 成功，公开站点在线冒烟与离线冒烟均通过。

## 13. 明确保留的限制

- 8,818 条名称索引有公开行级来源，但不等于《中国药典》收载；只有现有证据层明确标记的逐名药典证据才可称药典核验。
- TCM_KG 继续只称“公开资料整理”。
- origin 继续只称“资料记录地区”，不称道地产地。
- 古方剂量继续保留原始单位，不做现代处方换算。
- 图片只证明来源生物，不证明药用部位、炮制状态、功效或安全性。
- PWA 不承诺全部 65MB 图片和所有未访问目录离线可用。
- 本轮不恢复不完整的英文界面，也不引入账号、云同步或遥测。
